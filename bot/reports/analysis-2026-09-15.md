## 2. The reconcile bug, with evidence

Testnet log, 2026-09-10 (a `hash_supertrend` BTC short of 0.0026 opened
2026-09-09 20:00:39):

```
03:15:04 [ERROR]   hypertrade.exchange.hyperliquid: Failed to fetch user state
03:15:04 [WARNING] hypertrade.db.repo: Reconcile: closed orphan: hash_supertrend short 0.002558 BTC (no exchange position)
03:15:04 [INFO]    hypertrade.engine.runner: Reset in-memory state for hash_supertrend (DB position was orphan-closed)
03:20:41 [WARNING] hypertrade.db.repo: Reconcile: closed exchange-orphan: short 0.00256 BTC @ ~78424.0 → fill status filled
```

The read failed, `get_positions()` swallowed it and returned an empty list,
pass 1 of reconcile closed the DB row with `exit_price = entry_price`,
`pnl = 0.0` and no `Trade` row, and the strategy was reset to flat. Pass 2,
five minutes later, found the real short on the exchange with no DB owner
and market-closed it — real fill, real fee, real PnL, recorded nowhere.

Same pattern in the database since 2026-05-29 (testnet, `positions` with
`pnl = 0`, `exit_price = entry_price`, and no `trades` row within ±2 min
of `closed_at`):

| Month | Closed | Phantom |
|---|---|---|
| 2026-05 | 52 | 11 |
| 2026-06 | 48 | 11 |
| 2026-07 | 48 | 16 |
| 2026-08 | 36 | 14 |
| 2026-09 (to 15th) | 23 | 7 |

Durations run from 35 minutes to 7 days, so the market always moved. Paper
mode has **zero** such rows (the paper exchange never fails a read).

The mechanism is settled, not inferred:

- All-time on testnet there are **59** such rows at **38** distinct
  `closed_at` timestamps; 19 of those timestamps carry 2–3 rows each
  (e.g. 2026-09-08 10:30:32 closed `keltner_breakout/ETH` and
  `daily_long_0830/BTC` together). One failed read flattens the whole book.
- In the last two weeks of testnet log there are 60 `Failed to fetch user
  state` tracebacks and 12 `closed orphan` lines; **each of the 12 is
  directly preceded by** `hyperliquid.utils.error.ServerError: (502, …Bad
  Gateway…)`. Reconcile only bites when its 5-minute schedule coincides with
  a 502, which is why the ratio is 1:5.
- `allow_multi_coin` was never flipped (no `allow_multi_coin set to` line in
  the log), and no two testnet positions on the same symbol overlapped in
  time since 05-29 — HyperLiquid netting is *not* the cause. The per-coin
  gate does have a related weakness though: it reads the DB only
  (`runner.py:895` → `repo.py:347-358`), so after a phantom close the
  exchange still holds size that the gate cannot see, and the synthesized
  flip-close (`runner.py:836-887`) runs *before* the gate (`:889-935`).
  Fixing the read-failure path removes the trigger for both.
- `reconcile_positions` is byte-identical between the running image
  (`b5f53c5`) and master; `hyperliquid.py` is untouched. Redeploying does
  not fix this — but #158's fetch-outage aggregator will at least make the
  502 bursts visible in Telegram.

Code (all on `master` @ `e8b64da`):

- `bot/hypertrade/exchange/hyperliquid.py:552-557` — `get_positions()` catches
  every exception and returns `[]`.
- `bot/hypertrade/db/repo.py:583-587` — reconcile's own "exchange read
  failed" guard is unreachable for the live exchange because of the above.
- `bot/hypertrade/db/repo.py:606-631` — orphan / wrong-side close writes
  `exit_price = entry_price`, `pnl = 0.0`, no `Trade` row.
- `bot/hypertrade/db/repo.py:664-689` — exchange-orphan market close, no
  `Trade` row, `order.status` not checked (a REJECTED close is still
  reported as an action; seen twice live).
- `bot/hypertrade/engine/runner.py:318-322` — reconcile results go to
  `logger.warning` only, never to the event bus, so Telegram never hears
  about any of it.
- `bot/hypertrade/main.py:79` — the same reconcile runs at boot, so a boot
  during an HL blip flattens the whole book.

Consequences:

- Per-strategy PnL, `/eval`, `/kelly`, the dashboard totals and the
  `MAX_DAILY_LOSS_USD` counter (`runner.py:701, 1221`) never see the PnL of
  these closes.
- The testnet equity moved **946.53 → 872.36 (-74.17)** since 05-29 while
  recorded closed PnL is **-34.34** and current unrealized is +3.54. The
  ~-40 gap is consistent with the unrecorded market closes plus their fees.
- Every strategy verdict in § 3 is therefore approximate.

Suggested fix (one PR, engine-only): make `get_positions()` / `get_balance()`
raise (or return `None`) on read failure and have `reconcile_positions` bail
when the read did not succeed; refuse to orphan-close more than one row when
the exchange returns zero positions without a second confirming read; price
orphan closes from `fetch_user_fills` and write a `Trade` row; publish an
`ErrorOccurred` whenever reconcile takes an action. Tests should cover
"read raises → no DB change" and "one row + empty exchange → second read
before close".
